# 第0章 从你的使用经验出发

> 本书其余部分假设你想造 Agent，所以直接讲源码。但每个"内部机制"其实都对应一个**你已经见过的使用现象**——你只是不知道它叫什么。本章是翻译器：把日常现象翻成全书的概念地图。看完本章再进任何一章，都不会迷路。

## 0.1 关于"它怎么记住事"（→ Ch5 Context 工程）

| 你见过的现象 | 背后的机制 | 一句话原理 |
|-------------|-----------|-----------|
| 长对话聊着聊着，弹出 *"Compacting conversation…"* 或它主动说"我压缩了之前的对话" | **compaction 压缩** | 上下文窗口（约 200K token）装不下几十轮历史，把老轮次摘要成几句话腾地方 |
| 压缩之后，它记得任务大意但**忘了早期细节**（比如某个具体文件名） | **摘要是有损的** | 重要结论保留，字面细节丢失——所以重要约定要写进 CLAUDE.md 而不是口头说 |
| `/context` 显示 token 用量百分比 | **token 预算** | Harness 随时估算用量（chars/4 快估），接近阈值就触发压缩 |

**投影（projection）你其实已经体验过**：压缩后 `--resume`，历史居然都还在，它也能继续干活——因为全量历史一直躺在磁盘上（Session 层），发给模型的只是每次请求现算的一个"子集视图"。压缩改的是视图，不是历史本身。类比：**磁盘上的完整录像（Session） vs 电视正在播的画面（Context）**。

## 0.2 关于"它怎么做事"（→ Ch3 Loop / Ch4 Tools）

| 你见过的现象 | 背后的机制 | 一句话原理 |
|-------------|-----------|-----------|
| 它一格一格显示 `⏺ Read(file)… ⏺ Edit(file)…` | **Loop 主循环** | 每轮 = 问模型 → 模型要调工具 → 执行 → 结果喂回 → 再问……直到模型不再要工具 |
| 工具输出偶尔被截断标注 `(+200 lines)` | **Truncate 截断** | 结果太大塞不下，统一截断保头尾 |
| 同时读三五个文件很快，写文件却一个个来 | **并行 vs 串行** | 只读可并行；写有副作用必须串行——`isConcurrencySafe` 默认 false 是安全底线 |
| 网络抖动时显示 *"Retrying…"* 后自己恢复 | **重试闸** | 指数退避重试；429 限流还会按服务端要求等指定时长 |
| 你按 Esc 打断，或打字插话它会转向新指令 | **打断语义（steer）** | 用户输入被排进队列，在下一轮/下一步边界插入——DeepSeek 的 Inbox 把这两档分得很细 |

## 0.3 关于"它怎么守规矩"（→ Ch11 安全 / Ch4 权限）

| 你见过的现象 | 背后的机制 | 一句话原理 |
|-------------|-----------|-----------|
| 弹窗 *"Allow Bash(rm …)? (y/n/always)"* | **权限横切 + 分级记忆** | 危险动作默认 ask；选 always 记住模板下次放行——deny > ask > allow 三级晶格 |
| plan mode 下它拒绝写文件，只输出计划 | **模式化权限** | 计划态禁写、只能落盘计划文件——防止"边想边改" |
| 配置了 MCP server 后凭空多出新工具 | **MCP 扩展** | 工具清单是动态组装的，且每次请求和提示词同快照 |

## 0.4 关于"它怎么记住你"（→ Ch7 Session / Ch14 进化派）

| 你见过的现象 | 背后的机制 | 一句话原理 |
|-------------|-----------|-----------|
| 崩溃/关机后 `--resume` 能接着上次聊 | **Session 可重放** | 每条消息先落盘再发给模型；turn/start 边界保证恢复点不丢 |
| 有时报错 *tool_use ids without tool_result* 之后又自己好了 | **悬垂调用自愈** | 上次崩溃残留了没回答的工具调用，启动时自动补一条合成结果 |
| 它自己更新 todo list / 写计划文件 | **显式规划容器** | 计划是文件不是聊天记录——可 review、可回滚 |
| 装了个 SKILL.md 后它多了一项本领 | **技能库** | Voyager 思想的落地：能力以文件形式外部累积，不重训模型 |

## 0.5 一个贯穿案例：十分钟使用会话的内部解剖

```
00:00  启动 claude                     → 读配置分层(user/project)、注入 CLAUDE.md、
                                          git status 进 system prompt        [Ch2 Prompt]
00:20  你提问"修复这个 bug"            → append(user/msg) 先落盘再发请求      [Ch7 Session]
00:25  它连读 5 个相关文件              → 只读并行 + 结果截断                 [Ch4 Tools]
01:30  弹窗 Allow Edit(app.py)?        → 权限晶格 ask 级                     [Ch11]
02:00  改完跑测试，失败，自动重读重改    → Loop 多轮采样-执行-回填              [Ch3]
08:00  /context 显示 78%               → chars/4 估算，逼近 window-13K 阈值   [Ch5]
09:00  你 Esc 插话"先别动测试文件"       → steer 入队，下轮生效                [Ch3]
10:00  完成。历史已完整落盘             → --resume 随时可回来                 [Ch7]
```

十分钟的普通使用，六件套全部登场了一遍。**本书后面所有章节，只是在放大这十分钟里的某一步。**

## 0.6 给使用者级读者的路线

1. 先把本章现象表过一遍，确认每个现象你都见过（没见过的去用一次 Claude Code/OpenCode 补齐）；
2. 读 Ch2 六件套——现在每个部件你都有体感了；
3. 按 Ch12 Stage A 跑通 Lab 1（200 行最小闭环），你会瞬间看懂 `⏺ Read…` 背后的代码长什么样；
4. 之后哪章卡住就回到本章对应现象重新对号——概念永远可以从使用经验重新进入。
