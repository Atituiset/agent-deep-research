# 前言

**这是一份关于 Agent Infrastructure 的深度研究报告。**

---

## 研究缘起

2026 年，Agent 产品开始从 Demo 走向生产，围绕 Agent Infra 的讨论几乎不涉及 API 怎么写、SQLite 怎么调、TFLite 怎么部署，而是一直在讨论：

- 产品为什么这样设计？
- AI 为什么会误报？
- 为什么需要 Context？
- 云端还是端侧？

这不是实现层面的讨论，而是**架构讨论**。

这也促使我们重新审视技术积累：从编译器到静态分析，从 CI 到研发平台，从 LLM 到 Agent，从 MCP 到推理部署——过去这些看似分散的经验，在 Agent Infra 这个新兴方向上，串成了一条线。

**本报告是对整个 Agent Infra 领域的系统性研究。**

## 研究方法

本报告通过 **deep-research workflow**（多路并行搜索 + 对抗性验证）完成：

- **5 个搜索角度**：全景综述、实践模式、局限与 tradeoff、行业招聘信号、学术前沿
- **23 个来源**：包括 arXiv 论文（MemGPT、A-MEM、FadeMem）、行业博客（Letta、HuggingFace）、招聘信息（ByteDance）、开源仓库
- **92 条主张**提取，**25 条**进入 3-vote 对抗性验证
- **4 条**通过验证（≥ 2/3 确认），**21 条**被否决
- 最终 **3 项高置信度发现** 纳入核心论述

> ⚠️ **可信度声明**：验证过程严格但并非完美。所有"已验证"发现均标注置信度（high/medium），被否决的观点及其否决原因见附录 B。行业信号主要来自 ByteDance 单点，多公司交叉验证尚不充分。本领域迭代极快（2025-2026），建议每 6 个月更新一次。
